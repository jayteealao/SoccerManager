# Plan: Data Schemas and Team Generator

## The Plan

Engine-core handed over a working loop whose two teams are built in code with every attribute at 60, a `Tuning::default()` with no bounds, an `owner.id` fixed at `local-cli`, and a tick file with 36 reserved header bytes. Four research passes found the seams exactly where the engine-core plan said they would be (`Simulation::new` at `sim.rs:72-74`, `Team::builtin`, `Attributes::uniform`, `Tuning::default`), found that serde alone cannot refuse an attribute of 120, and found that the registry holds none of `toml`, `garde`, `rand_distr`, or `uuid`. The probe of engine-core added one fact: a refused run leaves no record.

Eleven product-owner answers fixed the build. Files are JSON, because the slice criterion names `a.json`; validation is `garde` 0.23 with one bound per field held in code; the shipped content lives on disk only, in `content/` beside the binary, and a missing file exits non-zero naming its path; the runtime data folder is `SM_DATA_DIR` with a Windows default of `%LOCALAPPDATA%\SoccerManager`, and `owner.id` is created there on first run; both the saved `stats.json` and the tick-file header carry `owner.id` and `match.id`; the generator draws a bell curve from summed uniform draws with no new dependency and is reachable as a library call and as `engine-cli generate`; the built-in teams are deleted everywhere and three engine-core tests re-record their bounds; positions use ten codes; and both augmentation artifacts are re-authored for this slice with the engine-core versions kept under `history/`. The plan fixes the default attribute list at 36 names in four groups, touches 44 files in 20 steps, and carries four small probe carry-overs because the same command-line files are open.

Implement follows this plan from the workspace manifest inward, with the content files generated by the binary itself at step 17 so the shipped defaults and the generator never diverge. The top open risk is determinism: attributes move from one shared value to a per-player array with derived speeds, so the byte-identical test and a new same-seed generator test guard every verify.

## Proposed Change Strategy

Replace the seams in place and keep one code path. The loader is one generic function used by four file kinds, so every refusal has the same shape: kind, relative path, field path, reason. `Attributes` stays `Copy` as a fixed array of 50 bytes, and six derived values are computed once at load so the hot path does no name lookup; this holds NFR-1 (`yields-to: C2`) without touching the positional model. The generator is the single source of the two shipped default teams: implement runs it at step 17 and commits its output, so the defaults can never drift from the generator.

Identity follows the observability contract: `owner.id` is created once on the machine, `match.id` keeps the seed and a millisecond stamp, and both ride in `stats.json` and the tick header (PO plan Q3, Q4). NFR-7 (data validation, fail closed with a named error) is met by the loader; NFR-4 (same-machine determinism) is guarded by the existing byte-identical test plus a generator same-seed test. No intent-bearing decision is left open: every RIM is adjudicated, and the PO answered the eleven forks above.

3. **Loader.** Write `data/mod.rs`: `ContentDir` with `resolve(flag: Option<PathBuf>) -> Result<ContentDir>` trying the flag, `SM_CONTENT_DIR`, `./content`, then `<exe dir>/content`, and an `Io`-style error that lists every path tried; `relative(&self, path)` for signals; `load_json<T: DeserializeOwned + garde::Validate>(&self, kind, rel, expected_version, ctx: &T::Context) -> Result<T>` that reads the file (missing file: `Io` with the path), peeks `VersionOnly`, compares, deserializes, calls `validate_with(ctx)`, maps the first `Report` line to `Data`, and emits `content.loaded` or `content.refused`; `Content { attributes, tuning, rules, hash }` and `Content::load(&dir)`; `load_team(&dir_or_path, &schema)`; `Content::hash()` as 12 hex characters of SHA-256 over the five file bytes in order. Unit tests: version mismatch, unknown key, and a range violation each produce the documented message.
4. **Attribute schema.** Write `data/attributes.rs`: `Group` enum (`technical`, `mental`, `physical`, `goalkeeping`); `AttributeDef { name, group }` with `#[garde(length(min = 2, max = 32))]` on `name`; `AttributeSchema { schema_version, attributes }` with `#[garde(length(min = 30, max = 50), dive)]` and a custom check for unique names and for the six required names `pace`, `acceleration`, `passing`, `dribbling`, `tackling`, `positioning`; `index(&self, name) -> Option<usize>` from a `BTreeMap` built after load; `MAX_ATTRIBUTES = 50`. `ATTRIBUTES_VERSION = 1`.
5. **Tuning file.** Write `data/tuning.rs`: `TuningFile { schema_version, engine: Tuning, generator: GeneratorTuning, fatigue: FatigueTuning }`; `GeneratorTuning { squad_size: 22, slot_positions: [Position; 11], bench_positions: [Position; 11], per_position: BTreeMap<Position, GroupDist> }` where `GroupDist` holds `{ mean, spread }` per group with `#[garde(range(min = 1.0, max = 100.0))]` on means and `#[garde(range(min = 0.0, max = 40.0))]` on spreads; `FatigueTuning { minutes_to_half_stamina, recovery_per_day }` as placeholders with bounds. In `tuning.rs` derive `Serialize`, `Deserialize`, `garde::Validate`, add `#[serde(deny_unknown_fields)]`, and one `#[garde(range(...))]` per field at ten times the default on the upper side and zero on the lower side unless the field is a probability (0 to 1) or `dt` (0.005 to 0.1). Keep `impl Default`. `TUNING_VERSION = 1`.
6. **Rule pack.** Write `data/rules.rs`: `StoppageKind` enum (`kick_off`, `throw_in`, `corner`, `goal_kick`, `free_kick`, `penalty`, `goal`, `half_time`, `injury`); `Stoppage { kind, admits_tactics, admits_substitution }`; `RulePack { schema_version, halves: 2, half_minutes: 45, substitutions: { limit: 5, windows: 3 }, stoppages }` with ranges `halves 1..=2`, `half_minutes 1..=60`, `limit 0..=11`, `windows 0..=5`, and a custom check that every `StoppageKind` appears once. `RULES_VERSION = 1`.
7. **Team file.** Write `data/team.rs`: `Position` enum with the ten codes; `Kit { primary, secondary }` with a custom hex check; `Club { id, name, short_name, kit }` with lengths `id 3..=64`, `name 2..=48`, `short_name 2..=4`; `PlayerEntry { id, name, shirt: u8, position, attributes: BTreeMap<String, u8> }`; `TeamFile { schema_version, club, players }` with `#[garde(context(AttributeSchema))]`, `#[garde(length(min = 11, max = 40), dive)]` on `players`, and `#[garde(custom(check_squad))]` that names duplicates of `id` or `shirt`, a missing or unknown attribute, and a value outside 1..=100 as `"player {id}: attribute {name} is {value}; allowed 1 to 100"`. `TEAM_VERSION = 1`.
8. **Attributes on the player.** In `player.rs` replace the six-field struct with `Attributes { values: [u8; MAX_ATTRIBUTES], len: u8 }` (`Copy`), `get(index)`, and `from_entry(&BTreeMap, &AttributeSchema)`; add `Derived { max_speed, max_accel, passing, dribbling, tackling, positioning }` computed by `Derived::from(&Attributes, &AttributeSchema, &Tuning)` using the six required indices; `Player` gains `derived: Derived`; `max_speed()` and `max_accel()` read `derived`; delete `Attributes::uniform`.
