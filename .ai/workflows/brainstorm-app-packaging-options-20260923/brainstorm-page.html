Touchline packaging board

brainstorm · reopened · updated 2026-09-25

Where we are. Today the installed game starts the engine and opens the match page in the player's default browser tab. Reach, not the tab, drives the package choice.

The next release delivers one app window that can grow later to Steam and to a tablet or phone. The choice leans to Tauri 2, with Electron as the fallback. Unity, Godot, and Bevy are off the list. After the release, an Unreal probe runs as its own workflow, in place of the GPUI pitch probe.

The page talks to the engine through one interface with two paths: direct calls in the app, and the socket in a plain browser for tests, development, and replays. Engine errors are caught at the boundary. The app updates itself, registers the replay file type, and keeps saves in today’s folder. Signing and hosted CI wait, so the first trial proves Windows and Linux: a full match, a suite test in the app, and the same event stream on both paths.

Reopened: Unreal Engine. One engine for the long run draws you most, and a 3D match-day game is the long-run goal, kept for later. The licence rule now allows a proprietary engine host, and the 3D anti-reference is rewritten too. The Tauri app window still ships first. After that release, an Unreal probe runs as its own workflow in place of the GPUI probe. The probe uses no web page, because the Unreal browser widget is too weak. It has a flat 2D pitch and one dense native screen, and it links the Rust engine into Unreal in-process, passing the same byte stream the web page reads. It must play a full live match with a tactics change, a pause, and a second match, read recorded matches byte for byte, restart after an engine error, and pass Unreal tests. The sharpest risk is the bridge: the in-process link fights the Windows and Linux toolchains, and the probe now takes five to eight weeks after the release.
