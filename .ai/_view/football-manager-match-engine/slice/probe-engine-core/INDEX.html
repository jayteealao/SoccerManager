    The Probe

    Verify handed over a pass on all six criteria of engine-core with live evidence for the benchmark and two low-severity copy observations. This probe re-drove the release binary from a fresh build (commit 27d21f5) on the same reference machine, with a new seed (2026) beside the verified seed 42, and read every surface against the acceptance criteria, the charter constraints C2 and C4, and the surface-defect taxonomy.

    All six criteria held again: 270,000 ticks per 90-minute match, byte-identical files for one seed, zero validator violations on two seeds, a 397 ms median against a 2,000 ms budget, and clean exit codes for valid and invalid seeds. The tick dump showed one ball position and 22 player positions in every one of 3,000 records, which is C2 observed directly. Thirteen enumerated surfaces were driven; none was unreached. Five findings resulted, two at medium: the simulate --json help text names a dump path the binary does not write, and every failure inside a run emits prose on stderr and no structured record, so the outcome: error value the instrumentation contract defines is never produced. Both were re-observed from a clean state on three and four paths respectively.

    Next is a fix intake scoped to this probe slice, because every finding is local and none is above medium; the review stage can carry them as ledger items instead if the product owner prefers to batch. The top risk is unchanged from verify: realism is untuned, and nothing in this probe can decide it.

    5. Findings

      • Severity: medium
      • Class: ambiguous-copy (W8: the concrete path the help names must be the path the binary writes)
      • Surface: cli, simulate --json help text
      • Defect: the help reads “Also write a JSON Lines dump of every tick next to the tick file (<FILE>.jsonl)”. The binary replaces the extension instead of appending: match.ticks produced match.jsonl, two.dots.bin produced two.dots.jsonl, and only the extensionless noext produced noext.jsonl. A script that reads <FILE>.jsonl as documented finds no file.
      • Evidence: enumerate.help.txt, reobs-json-path.listing.txt, reobs-json-path-1..3.* (clean-state re-observation on three paths)
      • Suggested fix shape: pick one rule in the --json path derivation in engine-cli and make the help text state that rule; the smaller change is the help text.
      • Severity: medium
      • Class: branch-gap
      • Surface: cli, simulate and bench failure paths inside run()
      • Defect: the instrumentation contract (04b-instrument.md § rules) defines outcome as success, error, or abandoned, and charter C4 promises structured events for the observability pipeline. On every failure inside a run (invalid minutes, invalid matches, unwritable output path) the binary prints prose on stderr and no record on stdout, so the pipeline never sees a failed run and the error value is never produced. Argument-parse failures (exit 2) happen before a run starts and are not counted here.
      • Evidence: tax-branch-gap-minutes-0.*, tax-minutes-201.*, tax-branch-gap-bench-matches-0.*, tax-leak-missing-dir.* (four failure paths, both subcommands)
      • Suggested fix shape: emit the match-stats or run-report record with outcome: error and a reason field on the error branch of each run(), or record a product-owner decision that pre-run failures stay prose-only and narrow the contract’s outcome enum.
      • Severity: low
      • Class: ambiguous-copy (S5 in reverse: identical wording twice reads as two events)
      • Surface: cli, simulate with an unwritable --ticks-out path
      • Defect: the message repeats the operating-system text: “cannot create : io error: Access is denied. (os error 5): Access is denied. (os error 5)”. The error type’s display already includes its source and the binary prints the chain as well. Verify carried this as an informational item; it reproduced on two new paths.
      • Evidence: tax-leak-ticks-out-is-dir.stderr.txt, tax-leak-missing-dir.stderr.txt
      • Suggested fix shape: print either the display or the chain in the binary’s error reporting, not both.
      • Severity: low
      • Class: branch-gap (non-tty path)
      • Surface: cli, stderr diagnostics when stderr is a file
      • Defect: the tracing lines on stderr carry ANSI colour codes when stderr is redirected. Verify carried this as an informational item; it reproduced.
      • Evidence: c2-simulate-json-1m.stderr.txt

      • Severity: low
